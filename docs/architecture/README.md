## 1. 定位

**Personal AgentOS 是一台生成式的个人电脑。** 电脑在应用层能做的事情它都能做，比如开发和玩游戏、上网查资料、收发邮件、看电影、写文档和博客。这些应用不是预装的，而是用户和 Agent 在使用过程中不断生成、迭代、组合出来的。

三个核心特征：

1. **应用是生成的。** 产物有三类：JS 动态应用、本地编译的原生应用、云端构建后下载安装的应用包。
2. **所有应用天然支持统一协议。** 每个应用一诞生就带着接口和事件，Agent 和其他应用都能调用它、订阅它，宿主是唯一的路由和中转。传统系统要给存量应用「补」Agent 接口，这里**接口和应用一起诞生**。
3. **Agent 拥有极大权限。** Agent 是系统里的最高权限主体，可以主动订阅事件、调用任何应用、读写全部数据。安全不靠削减 Agent 的能力，而靠操作可回滚、全程可审计、在出口把关，以及管住「指令从哪里来」。

产品约束（已定）：只做 macOS；不上 Mac App Store；用户自带 API Key（支持 Anthropic 直连和 OpenRouter）。

**四个核心场景**（来自[交互设计稿](../design/README.md)，也是各阶段验收的锚点）：

| 场景 | 用户看到的 | 背后的模块 |
|---|---|---|
| 一句话生成应用 | 说「做个贪吃蛇」，Agent 写代码、运行、冒烟测试、截图自检、注册接口，应用在左侧长出来 | 02、03、04、05 |
| 应用之间互联 | 笔记里写一行 TODO，待办自动出现；Agent 用 `apps.search` 找到 `tasks.list` 回答「本周有什么待办」 | 05、06、08 |
| 自主行动与授权 | 外部邮件触发自动化：解析、建日程直接完成；准备回信时，因为上下文含外部内容，弹出系统确认框 | 00、02、07、09 |
| 撤销与回滚 | 活动流里每件事都能精确撤销和重做；应用回滚时数据保留；已经发出去的操作明确标为不可撤销 | 00、01、04、08 |

## 2. 设计原则

1. **数据长存，应用可抛。** 个人数据放在系统级数据层，应用只是数据之上的视图和工作流，随时可以重写或替换。应用不能假设自己是数据的唯一写入者。
2. **能用确定性服务的，就不要生成。** 网络协议、邮件收发、编解码、密钥都由可信的系统服务实现；生成的部分集中在界面、工作流和个性化上。**所有对外的副作用都必须经过这些服务**，它们就是系统的「出口」。
3. **对话是主入口，应用是固化的工作流。** 先让 Agent 直接办事；某件事反复出现，就把它固化成应用。
4. **最小可信内核，其余皆可生成。** 内核负责身份、权限、密钥、包管理、审计、回滚和恢复模式，这部分不可生成；外壳和所有应用都可以生成，坏了能一键回滚。
5. **体验像 Parallels，实现像 WSL2。** 用户看到的是一个独立完整的系统；界面一律在 Mac 上原生渲染，脏活累活交给一台看不见的 Linux 虚拟机。
6. **接口与应用同生，界面是接口的第一个调用方。** 每个应用分为无界面核心和界面两部分；界面修改用户数据，也要调用自己核心的工具。所以 Agent 能做的，和用户在界面上能做的天然一致。
7. **Agent 权力大，靠可回滚、可审计和出口把关兜底。** 能撤销的操作直接执行；不可逆的对外操作，在出口按用户选择的权限模式把关；判断依据是「指令和数据从哪里来」，而不是削减 Agent 的能力。
8. **自有接口定义为真相源，对齐开放标准。** 应用接口用 AgentOS 自己的接口定义描述，MCP、CLI 和 TS 存根都是它的投影；事件信封用 CloudEvents；应用界面兼容 MCP Apps。

**分层与信任：**

| 层 | 内容 | 可信度 | 可否生成 |
|---|---|---|---|
| 内核 | 身份、授权、运行、副作用记录、检查点、审计、包管理、回滚与恢复、路由与总线 | 可信 | 否 |
| 系统服务 | 数据层、网络、邮件、媒体、AI 等；对外的服务就是出口 | 可信 | 否（由我们实现，或用经过审核的 MCP 驱动） |
| Agent | Operator 和 Builder | 高权限 | 否（提示词和 Skill 可以迭代） |
| 外壳 | 启动台、Dock、小组件、主题 | 半可信 | **是**（授权框、确认框、活动流、设置除外） |
| 应用 | 所有生成的应用（核心和界面） | 最小权限 | **是** |
| 外部内容 | 网页、邮件、下载的文件 | 不可信数据 | — |

## 5. 关键流程

### 5.1 一句话生成一个应用

```
用户：「做个笔记应用」
 → 宿主创建运行（00）；Operator 判断这是造应用，调用 apps.create 交给 Builder（02）
 → 04 新建应用和 src/ 工作区；03 打开预热好的界面 WebView
 → Builder 依次写：SPEC.md → 数据模型（复用 notes 集合）→ interface.json → core.js → 契约测试 → 界面
 → 每次写文件，03 自动重载；Builder 调用 run_contract_tests、run_app、smoke_test、screenshot 自测，最多修 3 轮
 → 04 提交版本：接口校验、计算副作用上限、申请权限、跑契约测试、git 提交、切换 current
 → 05 注册接口；从这一刻起，Agent 和其他应用都能调用它
```

### 5.2 应用之间互联

```
用户在笔记界面写下「TODO 周五前交报告」
 → 界面调用自己核心的工具：agentos.self.call('update', …)（界面对共享数据只读）
 → 核心写入 notes 集合（08）→ 数据层自动发出领域事件 note.updated（06）
 → 06 投递给持有授权的订阅者：待办应用的核心（不在运行就由宿主拉起）
 → 待办核心调用 notes.get 读正文，抽出 TODO，写入 tasks → 发出 task.created，depth 1
 → Agent 的自动化订阅了 task.*：创建一个运行，设置周五提醒，记入活动流
```

### 5.3 自主行动与授权

```
邮件服务收到外部邮件 → 发出 mail.received（trust=untrusted）
 → 自动化被触发：宿主创建运行，委托链 = 创建者 → 自动化 → 运行，工具白名单在创建时已固定
 → 邮件正文先交给没有任何工具的单次模型调用，解析成结构化字段（02 第 3.5 节）
 → calendar.create：副作用等级 external（可补偿），直接执行
 → mail.send：等级 irreversible，且运行带污点 → 自动模式下宿主弹出确认框，显示收件人、内容和来源链路
 → 所有调用写进审计，运行和副作用出现在活动流
```

### 5.4 撤销与回滚

```
活动流里点「撤销」
 → 00 找到这次运行的副作用记录，按时间倒序逐条撤销
 → 数据写入：08 恢复到写入前的版本；之后有别的修改时只还原未冲突的字段
 → 应用版本：04 切回旧版本，数据保留
 → irreversible 的副作用：不可撤销，提示可以起草更正
 → 撤销本身也被记录，可以重做
```

## 6. 技术选型总表

| 领域 | 选型 | 理由 | 备选或补充 |
|---|---|---|---|
| 宿主 | Swift 6 + SwiftUI + AppKit；**最低 macOS 26** | 原生体验；WebKit、虚拟化、钥匙串都能直接控制；统一平台框架与 WebKit 调度基线 | — |
| 内核与数据存储 | 系统 sqlite3 C 接口（WAL、FTS5、绑定参数） | 数据、历史、事件和审计同事务 | 未来可换 GRDB，保持事务边界 |
| 应用界面 | WKWebView + 自定义 scheme + CSP + 内容规则列表 | 改完立即生效（约 5 ms）、隔离好、模型最擅长写 Web | — |
| 应用核心 | 专用隐藏 WKWebView（无界面核心宿主） | 完全复用界面的安全模型；需要 S1 验证 | 规模上来后评估 JSC + 沙箱化 XPC 进程 |
| 原生应用 | 固定 swiftc、ad-hoc 签名、Seatbelt 沙箱进程 | 编译不到 1 秒；能用 Metal、120 Hz 和系统框架 | 不做进程内 dylib |
| Agent 引擎 | Claude Agent SDK（TS），Bun 编译的 sidecar；单次模型调用直接用 Messages API | 完整 Agent 循环、hooks、会话现成；隔离解析不该带工具 | 协议形状对齐 ACP（已有 `claude-agent-acp` 适配器） |
| 模型 | 沿用 Anthropic `claude-opus-5-5` 默认；OpenRouter 可配置模型 ID | 沿用设计基线；重建质量评测尚未实跑 | 其他模型按实验性数据出口策略处理 |
| 应用接口 | 自有接口定义（`interface.json`，JSON Schema 子集）；MCP HTTP 2025-06-18 兼容驱动和 `aos` CLI 作为投影 | 能表达副作用上限、依赖和版本兼容；MCP 变动只影响一个投影 | 遗留 Mac 应用用 AppleScript、快捷指令、辅助功能接口做适配 |
| 事件总线 | 自建：CloudEvents 1.0 + SQLite 日志 | MCP 不覆盖应用之间的发布订阅；事件草案语义仍在变 | 对外时映射到 MCP 事件扩展 |
| 虚拟机 | Virtualization.framework；独立应用后端用 Python/Node/OCI | 使用系统框架、每应用磁盘隔离 | 云构建与 macOS 来宾按需 |
| VM 网络 | 无网卡；vsock 显式请求宿主出口，逐次授权域名 | 出站控制必须是强制的，而不是建议 | — |
| 云端构建 | 用户自有 GitHub Actions（`macos-26` runner，$0.062/分钟） | 不碰 Apple 的签名和许可红线，费用归用户 | 本地构建是主路径 |
| 工程 | XcodeGen + xcodebuild + Makefile；Swift Testing；GitHub Actions CI | 工程配置可以 diff 和审查 | — |

## 10. 术语

| 术语 | 含义 |
|---|---|
| 宿主 / 内核 | AgentOS.app 本体中可信、不可生成的部分（[00](00-kernel.md)） |
| 主体（principal） | 「谁在做这件事」：用户、Agent 运行、应用核心或界面、系统服务、自动化 |
| 运行（run） | 一次自主工作，例如一轮对话、一次自动化触发；权限、预算、标签、审计链路都挂在运行上 |
| 副作用记录（effect） | 一次写入或出口调用的记录，是活动流、撤销和审计的共同来源 |
| 出口（sink） | 能产生对外副作用的可信系统服务，例如 `net.fetch`、`mail.send`、`publish` |
| 副作用等级 | read / write / fetch / external / irreversible（[09](09-security.md) 第 3 节） |
| 信息流标签 | 可信度（trust）、污点（taint）、机密性（sensitivity），作用在运行、应用实例、数据记录上 |
| 能力授权（grant） | 可限定范围、可撤销的权限凭证，例如「订阅 `note.created`」 |
| 放行规则（rule） | 用户创建的出口例外，例如「发给 `*@partner.com` 时直接放行」 |
| Operator / Builder | Agent 的两种角色：直接替用户办事 / 造应用和改应用 |
| 核心（core）/ 界面（UI） | 应用的两部分：无界面的工具、订阅和数据逻辑 / 渲染和交互 |
| 接口定义（IDL） | 应用的 `interface.json`，接口的真相源 |
| 元工具 | Agent 常驻的 `apps.search`、`apps.describe`、`apps.call` |
| 领域事件 | 数据层在集合写入后自动发出的事件，例如 `note.created` |
| A / B / C 类产物 | JS 动态应用 / 本地编译的原生应用 / 云端构建的应用包 |
| `.agentpkg` | 统一的应用包格式 |
| Workbench VM | 后台的 Linux 工作间虚拟机 |
| 活动流 | Agent 和自动化自主行动的记录，能撤销的都能撤销 |
