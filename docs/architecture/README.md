## 1. 定位

**Personal AgentOS 是一台生成式的个人电脑。** 电脑在应用层能做的事情它都能做，比如开发和玩游戏、上网查资料、收发邮件、看电影、写文档和博客。这些应用不是预装的，而是用户和 Agent 在使用过程中不断生成、迭代、组合出来的。

三个核心特征：

1. **应用是生成的。** 产物有三类：JS 动态应用、本地编译的原生应用、云端构建后下载安装的应用包。
2. **所有应用天然支持统一协议。** 每个应用都是一个 MCP Server，同时有 CLI 投影。AgentOS 能控制每一个应用，应用之间也能经 AgentOS 全局通讯和订阅。传统系统是给存量应用「补」Agent 接口，而这里**接口和应用一起诞生**，可以做到 100% 覆盖。
3. **Agent 拥有极大权限。** Agent 是系统里的最高权限主体，可以主动订阅事件、调用任何应用、读写全部数据。安全不靠削减 Agent 的能力，而靠操作可回滚、全程可审计，以及管住「指令从哪里来」。

产品约束（已定）：只做 macOS；不上 Mac App Store；用户自带 API Key（支持 Anthropic 直连和 OpenRouter）。

## 2. 设计原则

1. **数据长存，应用可抛。** 个人数据放在系统级数据层，应用只是数据之上的视图和工作流，随时可以重写或替换。
2. **能用确定性服务的，就不要生成。** 网络协议、邮件收发、编解码、密钥都由可信的系统服务实现；生成的部分集中在界面、工作流和个性化上。
3. **对话是主入口，应用是固化的工作流。** 先让 Agent 直接办事；某件事反复出现，就把它固化成应用。
4. **最小可信内核，其余皆可生成。** 内核负责权限、密钥、包管理、回滚和恢复模式，这部分不可生成；外壳和所有应用都可以生成，坏了能一键回滚。
5. **体验像 Parallels，实现像 WSL2。** 用户看到的是一个独立完整的系统；底层的分工是：界面一律在 Mac 上原生渲染，脏活累活交给一台看不见的 Linux 虚拟机。
6. **接口与应用同生。** Builder 每生成一个应用，都必须同时交付它的 MCP 接口、事件声明、Skill 说明和契约测试。
7. **Agent 权力大，靠可回滚和可审计兜底。** 能撤销的操作直接执行；只有不可逆的对外操作，才按用户选择的模式把关。
8. **对齐开放标准。** 应用接口用 MCP，事件格式用 CloudEvents，并尽量向 MCP 事件草案靠拢；应用界面兼容 MCP Apps。

```
┌──────────────────────────── AgentOS.app（宿主，可信内核）────────────────────────────┐
│ 01 外壳：桌面 / 启动台 / 窗口 / 活动流 / 授权确认（可信）       对话：Agent 主入口      │
│ ┌──────── 03 应用运行时 ─────────────┐  ┌──────── 07 系统服务 ───────────────────────┐ │
│ │ A：JS 应用（沙箱 WebView，默认）     │  │ 网络 · 搜索 · 浏览器 · 邮件 · 媒体 · AI       │ │
│ │ B/C：原生应用（Seatbelt 沙箱进程）   │  │ 通知 · 后台任务 · Intent · UI 组件 · MCP 驱动  │ │
│ │ W：WASM 模块                         │  │ 08 个人数据层：集合 + 文件 + 历史             │ │
│ └─────────────────────────────────────┘  └────────────────────────────────────────────┘ │
│ ┌──────── 05 应用协议 + 06 事件总线 ──────────────────────────────────────────────────┐ │
│ │ MCP Router（宿主是唯一客户端）· Event Broker（CloudEvents，SQLite 日志）· CLI（aos） │ │
│ └──────────────────────────────────────────────────────────────────────────────────────┘ │
│ 09 安全：能力授权 · Agent 权限模式 · 污点标记 · 宿主确认框 · 审计 · 出站代理 · 密钥        │
│ 04 包管理：.agentpkg 校验 / 安装 / 版本 / 回滚        02 Agent 引擎（sidecar 子进程）    │
└───────────────┬───────────────────────────────────────────────┬──────────────────────┘
                │ vsock / virtiofs                                │ HTTPS
┌───────────────▼────────────────────────────┐   ┌───────────────▼──────────────────────┐
│ 10 工作间虚拟机（Linux，Apple Containerization）│   │ 模型服务商：Anthropic / OpenRouter     │
│ 工具链 · 应用后端 · 定时任务 · 无头浏览器       │   │ 云端构建：用户自己的 GitHub Actions    │
│ 临时微虚拟机：运行不可信代码                    │   └──────────────────────────────────────┘
└────────────────────────────────────────────┘
```

**分层与信任：**

| 层 | 内容 | 可信度 | 可否生成 |
|---|---|---|---|
| 内核 | 包管理、权限、密钥、审计、回滚与恢复、协议路由与总线 | 可信 | 否 |
| 系统服务 | 数据层、网络、邮件、媒体、AI 等 | 可信 | 否（由我们实现，或用经过审核的 MCP 驱动） |
| Agent | Builder 和 Operator | 高权限 | 否（提示词和 Skill 可以迭代） |
| 外壳 | 启动台、Dock、小组件、主题 | 半可信 | **是**（授权确认框、活动流、设置除外） |
| 应用 | 所有生成的应用 | 最小权限 | **是** |
| 外部内容 | 网页、邮件、下载的文件 | 不可信数据 | — |

## 5. 关键流程

### 5.1 一句话生成一个应用（P0 已跑通，P1 在其上增加接口生成）

```
用户：「做个笔记应用」
 → 01 外壳在包管理里新建应用 → 03 运行时打开一个预热好的空白 WebView
 → 02 Builder 写代码，左侧实时显示进度 → 文件一变化，运行时就自动重载
 → Builder 依次调用 run_app、smoke_test、screenshot 自测，发现问题就修，最多 3 轮
 → Builder 同时生成 interface（MCP 工具和事件）、SKILL.md、契约测试          ← P1
 → 04 打包并登记版本 → 05/06 注册工具和事件 → 09 生成权限授权
```

### 5.2 应用之间的事件订阅

```
笔记应用：agentos.events.emit("note.created", {id})
 → 06 总线：宿主给事件盖上来源，打上可信度标记，写入日志
 → 投递给持有授权的订阅者（例如待办应用，以及 Agent）
 → 待办应用调用 agentos.call("notes.get", {id}) 读取正文，05 路由，09 检查授权
```

### 5.3 Agent 主动订阅与自动化

```
Agent：events.subscribe("mail.received", 过滤条件) + automation.create(计划)
 → 事件到达 → 不可信内容先交给没有工具的隔离模型，解析成结构化字段
 → 按计划执行：调用的工具白名单在创建时就已固定
 → 不可逆的对外操作，按当前权限模式决定是否确认 → 记入活动流（可撤销）和审计日志
```

## 6. 技术选型总表

| 领域 | 选型 | 理由 | 备选或补充 |
|---|---|---|---|
| 宿主 | Swift 6 + SwiftUI + AppKit | 原生体验，WebKit、虚拟化、钥匙串都能直接控制 | 跨平台需求出现时，前端层可迁到 Tauri |
| 默认运行时 | WKWebView + 自定义 scheme + CSP | 改完立即生效（约 5 ms）、安全隔离、模型最擅长写 Web | — |
| 原生应用 | swiftc / SwiftPM，ad-hoc 签名，Seatbelt 沙箱进程 | 编译不到 1 秒；能用 Metal、120 Hz 和系统框架 | 不做进程内 dylib（会拖垮宿主，也卸载不掉） |
| Agent 引擎 | Claude Agent SDK（TS），用 Bun 编译成 sidecar 子进程 | 完整的 Agent 循环、hooks、会话、MCP 都现成 | Swift 原生循环；协议形状对齐 ACP，引擎可替换 |
| 模型 | Anthropic `claude-opus-5-5`（默认）；OpenRouter 上的 `anthropic/claude-*` | 质量最高；OpenRouter 方便支付和选模型 | 其他模型属于实验性支持 |
| 应用协议 | MCP（基线版本 2026-07-28）+ CLI 投影 | 开放标准，Agent 原生理解 | 遗留应用用 AppleScript、快捷指令、辅助功能接口做适配 |
| 事件总线 | 自建：CloudEvents 1.0 + SQLite 日志 | MCP 不覆盖应用之间的发布订阅 | 向 MCP Triggers & Events 草案靠拢 |
| 虚拟机 | Apple Containerization（Swift，Apache-2.0） | 能直接嵌进我们的进程，启动亚秒级 | 底层是 Virtualization.framework |
| 云端构建 | 用户自有 GitHub Actions（`macos-26` runner） | 不碰 Apple 的签名和许可红线，费用归用户 | 本地构建是主路径 |
| 工程 | XcodeGen + xcodebuild + Makefile | 工程配置可以 diff 和审查 | — |

## 10. 术语

| 术语 | 含义 |
|---|---|
| 宿主 / 内核 | AgentOS.app 本体中可信、不可生成的部分 |
| Builder / Operator | Agent 的两种角色：造应用和改应用 / 直接替用户办事 |
| A / B / C 类产物 | JS 动态应用 / 本地编译的原生应用 / 云端构建的应用包 |
| `.agentpkg` | 统一的应用包格式 |
| interface | 应用清单里声明的 MCP 工具、事件、订阅和调用 |
| 能力授权（grant） | 可限定范围、可撤销的权限凭证，例如「订阅 `mail.received`」 |
| effects | 宿主判定的工具副作用等级：read / write / external / destructive |
| 污点（taint） | 标记数据来自不可信来源，并随数据一起传播 |
| Workbench VM | 后台的 Linux 工作间虚拟机 |
| 活动流 | Agent 自主行动的记录，每条都可以撤销 |
