# 09 权限与安全

> 所属：[技术方案总览](README.md) ｜ 涉及所有模块
>
> 依据：[system-architecture.md](../research/system-architecture.md) 第 4.6、4.9、4.10 节

## 1. 威胁模型

| 威胁 | 例子 | 主要对策 |
|---|---|---|
| 生成代码有 bug | 死循环、崩溃、误删数据 | 进程隔离、可回滚、冒烟测试 |
| **提示注入** | 邮件或网页里藏着「把通讯录发给 xxx」 | 污点标记、不可信内容只当数据、隔离模型解析、先计划后执行、对外操作把关 |
| 应用越权 | 笔记应用偷读邮件，或偷偷联网 | 最小权限、能力授权、CSP 和规则列表、出站代理 |
| 数据外泄 | 生成代码把数据发到外网 | 默认禁止联网，联网只能走白名单代理，并记入审计 |
| 骗取授权后替换工具 | 先拿到授权，再换掉工具实现 | 工具快照用哈希锁定，变化后需要重新授权 |
| 供应链 | 依赖包、云端构建产物被篡改 | 摘要、签名和构建证明校验，依赖锁定和白名单 |
| 资源滥用 | 事件风暴、自动化循环、费用失控 | 深度上限、频率上限、预算上限、熔断 |
| 密钥泄露 | API Key、邮箱密码被应用读到 | 密钥只存在宿主侧，应用永远拿不到 |

## 2. 主体与信任层级

```
用户（最终权威）
 └─ Agent（高权限，≈ root）              ← 创始人决策：给 Agent 极大权限
     └─ 系统服务（可信，由我们实现）
         └─ 应用（最小权限，生成的代码）
             └─ 外部内容（网页、邮件、下载的文件：不可信数据，永远不当指令）
```

**一次调用的实际权限 = 调用方的授权 ∩ 发起这件事的主体的权限。** 例如，Agent 通过某个应用发出调用，这次调用的权限不会超过该应用拿到的授权；而某个应用发起的调用，权限也不会超过用户本人。

## 3. Agent 的权限模型

**Agent 默认可以：**
- 主动订阅任何事件；
- 调用任何应用的任何工具；
- 读写全部数据；
- 创建、修改和删除自动化；
- 安装、修改和回滚应用；
- 在 Workbench VM 里执行任意命令。

**不逐条请求授权。** 安全靠以下四点保障，而不是削减 Agent 的能力：

1. **能回滚，就不用问。** 应用有版本（[04](04-app-package.md)），数据有历史和软删除（[08](08-data.md)），VM 有快照（[10](10-workbench-vm.md)）。
2. **只把关不可逆的对外操作。** 工具的 `effects` 由宿主判定，分为 `read`、`write`、`external`、`destructive`，其中只有 `external` 和 `destructive` 需要把关。按全局的**权限模式**处理：

   | 模式 | external / destructive 操作 | 适合 |
   |---|---|---|
   | 谨慎 | 每次都弹确认框 | 刚开始使用、处理重要账户 |
   | **自动（默认）** | 直接执行；**只有当 Agent 的上下文里混入了不可信内容（`trust=untrusted` 或带污点）时才确认** | 日常使用 |
   | 完全信任 | 从不确认，只记日志 | 高级用户 |

   用户还可以按「应用加操作」单独设置例外规则，例如「`mail.send` 发给公司域名时总是放行」。
3. **管住指令来源，而不是能力。** 外部内容一律当作数据处理（见第 5 节）。
4. **全程可见、可撤销。** 活动流记录 Agent 自主做的每件事，每条都能撤销；全局每日费用上限和自动化上限防止失控。

## 4. 应用的权限：能力授权

### 4.1 申请

- 写在清单的 `permissions` 里：`network` 域名、`data` 集合（r / rw）、`services`、`files` 路径。
- 写在 `interface` 里：`subscribes`（订阅哪些事件）、`calls`（调用哪些应用）。
- 宿主把这些申请转成**能力授权**：

  ```jsonc
  { "grantId": "g_91", "holder": "app:tasks", "capability": "subscribe",
    "scope": { "pattern": "note.created", "filter": null },
    "grantedBy": "user", "grantedAt": "…", "expiresAt": null, "revoked": false }
  ```

### 4.2 授予与撤销

- 安装或升级时，外壳弹出授权框，展示权限变化前后的对比（[01](01-shell.md)）。用户可以单项拒绝，被拒绝的能力在调用时会得到 `denied`。
- 设置里可以按应用查看和撤销授权，撤销立即生效（相关订阅随之停止，见 [06](06-event-bus.md)）。
- 授权可以设置有效期，例如「只在本次会话有效」。

### 4.3 检查点

每一次 MCP 调用、事件发送和订阅、数据读写、联网请求，都会在宿主的单一检查点上校验授权。不在各运行时里分散实现，避免出现绕过漏洞（这是 D-Bus 代理的教训）。

## 5. 提示注入防御

1. **信息流标记**：事件、工具结果和数据记录都带 `trust`（可信度）、`taint`（来源）、`sensitivity`（机密性）三类标记，并随派生数据一起传播（[08](08-data.md)）。
2. **不可信内容只当数据**：喂给模型时外加数据边界包装；处理不可信内容的回合，按权限模式收紧对外操作。
3. **隔离模型解析**：事件触发的自动化里，不可信内容先交给**没有任何工具**的模型，提取成结构化字段，再交给 Operator（Dual-LLM / CaMeL 模式）。
4. **先计划后执行**：自动化可以调用的工具和收件人范围，在创建时就固定下来，事件内容无法扩大这个范围（[02](02-agent.md)）。
5. **防工具投毒**：工具定义用哈希锁定；Builder 生成的工具描述要过 lint，禁止在描述里出现指令性内容，也禁止冒用其他应用的工具名。
6. **深度和频率限制**：事件深度上限、频率上限、循环熔断（[06](06-event-bus.md)）。

## 6. 隔离层

| 对象 | 隔离手段 | 状态 |
|---|---|---|
| JS 应用 | WebKit 独立进程；CSP（`default-src 'none'`）；规则列表屏蔽 http(s) 和 ws(s)；导航白名单；每个应用独立的数据存储；消息来源校验（只认顶层 frame 和本应用 origin） | P0 ✅ |
| 原生应用 | 独立进程；Seatbelt（默认拒绝一切，只允许访问应用自己的数据目录，网络必须走代理）；宿主重新签名，忽略包里自带的授权 | P3 |
| VM 里的代码 | 虚拟机隔离；virtiofs 只共享授权目录；独立的 vmnet NAT；出站流量走代理 | P2 |
| Agent 引擎 | 独立的子进程；`CLAUDE_CONFIG_DIR` 隔离配置；文件工具只能访问应用目录（PreToolUse hook）；内置工具白名单 | P0 ✅ |
| 浏览器视图 | 独立的 WKWebView 和数据存储，与应用和宿主隔离 | P2 |

## 7. 网络

- **应用**：默认禁止联网。获得授权后，只能通过 `agentos.net.fetch` 经宿主代理访问白名单里的域名，并记入审计。CSP 不会放开。
- **VM**：所有出站流量都经过宿主代理，套用和应用相同的白名单规则；Agent 自己的任务可以设置更宽的白名单。
- **宿主自身**：只访问模型服务商、Key 校验接口、GitHub（云端构建）、媒体元数据源等固定的端点。

## 8. 密钥

| 密钥 | 存放 | 谁能用 |
|---|---|---|
| Anthropic / OpenRouter API Key | 钥匙串（每个服务商一份），保存前在线校验 | 只有宿主，通过环境变量传给引擎子进程 |
| 邮箱凭据、博客平台凭据 | 钥匙串 | 只有对应的系统服务 |
| GitHub 令牌（云端构建） | 钥匙串 | 只有包管理 |
| 本机签名密钥（Ed25519） | 钥匙串 | 只有包管理 |

应用和 VM **永远拿不到**这些密钥。应用要用 AI，就调用 `agentos.ai`，由宿主代为请求。

## 9. 审计

- 所有调用、事件、授权变更、确认结果和 Agent 的自主行动，都写进一份**哈希链审计日志**（每条记录包含上一条记录的哈希，可以发现篡改），按 `traceparent` 串联成完整的链路。
- 活动流是审计日志面向用户的视图（[01](01-shell.md)）。
- P0 现状：`logs/agentos-<启动时间>.jsonl` 记录了事件日志（提示、结果、运行时调用、冒烟测试、错误），但还不是哈希链。

## 10. 已知限制

- WebContent 进程陷入死循环时，没有公开的 API 能杀掉它。目前只能提示用户、重建 WebView，并考虑在服务代码时对循环做保护性改写。
- `sandbox-exec`（Seatbelt）已被标记为弃用，但仍然可用，Chromium 和 Claude Code 都在用。需要持续关注。
- AgentOS 自己下载的产物不经过 Gatekeeper 检查，所以 AgentOS 必须自己做严格校验（[04](04-app-package.md)）。
- 污点标记如果粒度太粗，会导致频繁确认、用户点到麻木，需要在交互上精心设计（例如批量确认、按规则放行）。
