# 01 系统外壳与交互

> 所属：[技术方案总览](README.md) ｜ 相关：[02 Agent](02-agent.md)、[03 运行时](03-app-runtime.md)、[09 安全](09-security.md)

## 1. 职责

外壳是用户看到的「这台电脑」本身，负责：

- **窗口与布局**：多个应用同时打开，可以平铺、分标签，也可以弹出成独立窗口，还有全屏桌面模式。
- **入口**：对话面板（Agent 主入口）、启动台、Dock、全局搜索。
- **可信交互面**：授权弹窗、敏感操作确认框、活动流、设置、恢复模式。这些必须由宿主绘制，应用无法伪造。
- **系统体验**：通知中心、小组件、主题。

外壳分为两层：

| 层 | 内容 | 实现 | 可否生成 |
|---|---|---|---|
| 可信外壳 | 窗口管理、对话面板、授权和确认框、活动流、设置、恢复模式 | Swift / SwiftUI | 否 |
| 可生成外壳 | 启动台、Dock、小组件、主题、桌面布局 | 运行在运行时里的特权 Web 应用 | **是**，坏了可以回滚（P4） |

## 3. 目标设计

### 3.1 布局与窗口

```
┌──────────────────────────── AgentOS 窗口 ──────────────────────────────┐
│ 菜单栏：AgentOS · 应用 · 窗口 ·（全屏桌面模式下显示系统托盘）             │
├───────────────────────────────────────────────┬────────────────────────┤
│ 应用区                                          │ 对话面板（可收起）       │
│ · 标签页或平铺显示多个应用                       │ · 全局 Agent 对话        │
│ · 每个应用可以「弹出」成独立的 Mac 窗口          │ · 自动带上当前应用上下文  │
│ · 没有打开应用时显示启动台                       │ · 可以用 @ 指定某个应用   │
├───────────────────────────────────────────────┴────────────────────────┤
│ Dock：常用应用 · 正在运行的应用 · 活动流入口 · 通知                        │
└─────────────────────────────────────────────────────────────────────────┘
```

- **多应用**：每个应用有自己的运行时实例（见 [03](03-app-runtime.md)）。处于后台的应用会被挂起，正在执行 Agent 任务的应用不受影响。
- **弹出窗口**：把应用的视图挂到一个新的 `NSWindow` 上，运行时实例保持不变。B/C 类原生应用本来就是独立窗口。
- **全屏桌面模式**：AgentOS 占据一个独立的桌面空间，菜单栏和 Dock 都由 AgentOS 绘制，带来「进入另一个系统」的感觉，也就是「体验像 Parallels」的那部分。

### 3.2 对话面板（Agent 主入口）

- 对话可以是全局的，也可以绑定到某个应用。全局对话交给 Operator，涉及造应用时转给 Builder（见 [02](02-agent.md)）。
- **自动带上的上下文**：当前应用的 id、清单摘要、`agentos.expose` 暴露的状态、最近的报错。用户也可以手动附上截图或选中的内容。
- **工具调用可视化**：沿用 P0 的工具卡片，补充调用其他应用（`mail.search`）、事件订阅、自动化创建等卡片类型。
- 「固化成应用」：Operator 发现某类任务反复出现时，在对话里提出建议，用户一键交给 Builder。

### 3.3 可信交互面

| 组件 | 作用 | 要求 |
|---|---|---|
| **授权弹窗** | 应用首次申请权限（网络、数据集合、订阅、调用），以及升级后权限有变化时 | 展示权限变化前后的对比；可以单项拒绝；之后可以在设置里撤销 |
| **确认框** | 不可逆的对外操作，例如发邮件、发布、付款、删除 AgentOS 之外的文件，具体规则见 [09](09-security.md) | 由宿主绘制，展示完整参数（收件人、内容摘要）和来源链路（哪个应用、哪次事件、有没有污点） |
| **活动流** | 记录 Agent 和自动化自主做过的每一件事 | 按时间倒序；每条显示触发原因、调用了什么、结果；**每条都能撤销**（见 [08](08-data.md) 和 [04](04-app-package.md) 的回滚） |
| **设置** | 服务商和 Key、模型、Agent 权限模式、各应用的权限、预算上限、数据与备份 | — |
| **恢复模式** | 外壳或某个应用坏了时进入 | 启动时按住 ⌥，或外壳连续崩溃时自动进入；可以回滚外壳或应用版本，也可以用安全外壳启动 |

### 3.4 可生成外壳（P4）

- 启动台、Dock、小组件、主题都是带特权接口的 Web 应用。特权接口包括：列出应用、启动应用、读取活动流摘要、读取通知。
- 用户可以对 Agent 说「把我的桌面改成……」，由 Builder 修改外壳应用；修改后自动跑外壳的冒烟测试，失败就回滚。
- **可信外壳永远不可生成**，生成的外壳无法遮挡或模仿授权框和确认框。确认框绘制在独立的系统层窗口里。

### 3.5 通知中心

- 来源有三种：应用（`agentos.notify`，需要权限）、系统服务（例如新邮件）、Agent（自动化的结果、需要用户确认的事项）。
- 通知可以转成 macOS 系统通知，系统通知权限由宿主申请。

## 4. 与其他模块的接口

| 方向 | 接口 |
|---|---|
| 外壳 → 02 | 提交对话请求（`session/prompt`）、取消；接收流式事件（`session/update`） |
| 外壳 → 03 | 打开、关闭、挂起、弹出应用；拿到当前应用的上下文 |
| 外壳 → 04 | 查询应用列表、版本列表，执行回滚 |
| 09 → 外壳 | 请求显示授权弹窗或确认框（异步等待用户决定） |
| 02 / 06 → 外壳 | 写入活动流，发送通知 |

## 5. 里程碑

| 阶段 | 内容 |
|---|---|
| P0 ✅ | 单窗口、启动台、对话、设置 |
| P1 | 同时打开多个应用（标签页）；授权弹窗和确认框；活动流 v1（显示加撤销）；设置里加入 Agent 权限模式和应用权限页 |
| P2 | 全局对话交给 Operator；应用弹出成独立窗口；全局搜索 |
| P3 | 通知中心；原生应用窗口统一管理 |
| P4 | 全屏桌面模式；可生成外壳；恢复模式 |

## 6. 待定问题

- 平铺、标签页、自由窗口，默认用哪种布局？建议默认标签页，可以切换成平铺。
- 对话面板是全局唯一，还是每个应用一个对话？建议全局对话加上应用上下文，同时保留每个应用的对话历史。
