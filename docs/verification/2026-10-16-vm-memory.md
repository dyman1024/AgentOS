# VM 完整内存恢复诊断与验收（2026-10-16）

完整内存恢复在现有 Mac 的解锁会话中可用，ad-hoc 签名即可。当前复现的 `VZErrorDomain Code 12 / permission denied` 与锁屏时系统密钥解密被拒绝相对应，不是缺少 Apple 开发者证书。本轮没有改变系统锁屏、钥匙串、安全策略或框架加密行为。

## 证据与结论

环境：macOS 26.5.1（25F80）、Apple M5 Pro、Xcode 26.6（17F113）。最小程序仅依赖系统 Virtualization.framework，配置 2 vCPU、512 MiB、只读开发磁盘、同一个持久机器标识。工作间集成使用实际的 1 GiB、vsock、串口配置。

Apple 说明保存文件经硬件加密，绑定原 Mac 和用户；SDK 头文件也说明异机恢复可返回 permission denied。因此，单独看到 Code 12 不能推出“缺证书”，也不能把所有 Code 12 都解释为锁屏。当前结论由上面的同机、同程序、两种签名和会话状态对照支持。[Apple WWDC23](https://developer.apple.com/videos/play/wwdc2023/10007/)；[restore API](https://developer.apple.com/documentation/virtualization/vzvirtualmachine/restoremachinestatefrom(url:completionhandler:))。

完整本地日志保留在开发环境，公开摘录去掉本机路径、证书身份与密钥标识，见[结果摘录](2026-10-16-vm-memory.txt)。未主动锁定用户桌面；锁屏为测试期间实际观察到的状态。

## 已修复的实现问题

1. **失败回退丢失最近写入。** 损坏内存文件的故障注入发现，直接停止 VM 会丢失尚在 Linux 页缓存中的写入。现在恢复前先同步当前来宾，再停止并保留当前磁盘；恢复失败会还原该磁盘。测试确认最近写入仍为 `latest`。
2. **生命周期可在 await 期间交错。** 快照与恢复现在独占 `checkpointing`；并发命令、启动、停止和快照均拒绝。快照使用临时目录，完成后才发布。
3. **错误缺少可操作信息。** `vm_restore_failed` 保留底层域、码、原因和 `diskRestored`，提示原 Mac、原用户、解锁后重试。若磁盘回退自身失败，返回独立错误并保留备份；不吞掉失败。
4. **恢复后的常驻进程可能被错误闲置暂停。** 新宿主未必知道保存时的服务清单。完整恢复的 VM 不自动闲置暂停，直到显式停止或冷启动；这会增加驻留资源占用。

恢复失败保持 VM 停止，不自动采用冷启动。磁盘回退保护已确认写入，不恢复失败发生前的任意未落盘进程内存。快照失败也不发布半成品。

## 验收范围

| 验收 | 断言 |
|---|---|
| 内存连续性 | Python 后端只在堆中保存计数器；41 → 保存 → 99 → 恢复为 41 → 继续执行为 42 |
| 进程身份 | 随机 nonce、PID、Linux boot ID 与保存时一致 |
| 新宿主进程 | 父宿主停止 VM 后由新的 VMChecks 进程读取同一快照，重新验证堆状态与磁盘 |
| 暂停状态 | 从闲置暂停的工作间进入恢复流程 |
| 并发保护 | 保存期间写入与停止请求失败，保存结束后独占状态释放 |
| 失败回退 | 无效内存文件拒绝；VM 不自行启动；原磁盘的 `latest` 写入仍可读 |
| 授权边界 | 恢复后仍拒绝伪造宿主令牌；没有恢复一次命令的有效宿主授权 |
| 显式冷恢复 | 磁盘内容还原，boot ID 改变；不计为内存连续性通过 |
| 原有集成 | 无网卡、宿主授权 HTTPS、Node/OCI 契约隔离、撤权、镜像更新及临时磁盘清理 |

## 后续使用与验收条件

- **日常恢复：** 在创建快照的 Mac 和用户下解锁，再显式重试。当前环境不需要购买或配置新证书。
- **需要锁屏后台无人值守恢复：** 当前环境不承诺支持。保持任务失败可见，等待用户解锁重试；不要关闭锁屏或绕过加密。若这是发行要求，应提供最小程序及脱敏日志给 Apple Feedback，并在支持的 OS/硬件矩阵验证。
- **跨机器、跨用户或系统升级：** 内存文件不是可移植包。配置或格式不兼容时保留原数据，由用户选择显式冷磁盘恢复；不把冷恢复标为完整内存恢复。
- **发行验证：** Developer ID、公证、签名更新和干净 Mac 仍为独立验收；本轮成功不替代这些条件。
