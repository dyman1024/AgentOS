## VM 实测

真实 VM 使用开发 ext4 和现有 LinuxKit 内核；运行本身不依赖 Docker。通过无硬件网卡、直接 socket 拒绝、未授权域名/伪造令牌拒绝、授权 HTTPS、服务持续运行、Node/OCI 后端独立契约环境、活跃后端持续状态、撤权、临时磁盘清理和冷磁盘快照恢复。

签名基础镜像选择、版本防重放、原有持久磁盘保留均实测通过，见 [VM 日志摘录](2026-10-16-vm.txt)。当前公共发行 kernel/rootfs、HTTPS 托管服务和可信发行公钥未配置。

完整内存恢复返回 `VZErrorDomain Code 12`。独立最小复现、无 vsock 配置和新进程恢复也失败；**未通过**，并未用冷启动冒充。冷磁盘恢复必须显式启用。

联调中两次出现 Swift 异步默认参数闭包的内存释放崩溃，堆栈指向 NetworkGateway 默认发送函数的 thunk。已将生产路径改为直接调用静态 HTTP 方法，测试注入闭包保留为可选参数；随后完整 VM 出站和 Node/OCI 集成通过。这是本次修复的回归，不代表对 Swift 编译器问题已有最终归因。

## 当前边界

声明式迁移限顶层字段和单个用户集合；跨应用联合迁移、按应用/运行的整组时间点恢复未实现。WASM 限 core module；原生固定 swiftc；OCI 限单平台 image-layout；自动化是固定工具序列；导出不含媒体原文件；已有 VM 磁盘不原地升级。详见 [重建方案](../architecture/12-rebuild-plan.md)。

这些限制和未通过项意味着：当前具备可继续验证的完整开发交付，**不能宣布整个产品或发行验收完成**。

Release 额外验证：Bun 引擎实际响应 JSON-RPC 未知方法并正常 EOF 退出，Claude 二进制 `--version` 启动成功，均不调用模型。Release 宿主本机启动则被 library validation 拒绝（ad-hoc 没有 Team ID，无法加载 Sparkle）。这不是未嵌入或漏签框架；未关闭安全校验来掩盖失败。CI 的 Release smoke 会明确报告该项 NOT RUN，使用真实 Apple 身份签名后才验证宿主启动/交接。
