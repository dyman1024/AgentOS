## 真实桌面操作

准备：`scripts/prepare-evolution-fixtures.py`。所有应用均为手写测试夹具；旧 P0 和用户正常数据未覆盖。

| 操作 | 观察到的结果 |
|---|---|
| 选择联合账本与联合报表 | 宿主预检、隔离测试后展示两个应用及 `amount` → `total` 的迁移计划 |
| 拒绝联合更新 | 两个活动版本仍为 `1.0.0+1`；记录 `amount=42`、修订 1 不变 |
| 批准联合更新 | 两个版本同时为 `1.0.0+2`；同一记录变成 `total=42`、修订 2；备份已保存 |
| 按应用恢复 | 预览 1 次写入、1 条记录，展开显示变更；恢复后只移除该应用新建记录，保留迁移前存在的记录 |
| 拒绝分组恢复 | 预览保留，数据未变 |
| 预览后另写一条记录，再批准 | 返回 `conflict: Recovery preview changed; preview again`，不执行过期恢复 |
| 从活动运行分组恢复 | 修复首次打开未带入 ID 的问题；复测自动选择 `jointledger.write` 对应运行，批准后原有 `total=42` 和独立的 `total=99` 均保留 |
| 选择可生成桌面 | 独立宿主确认窗请求批准；桌面显示夹具内容，能列出应用并打开笔记，宿主设置等控件保留 |
| 正常退出并重启 | 重新载入此前选择的桌面 |
| 桌面异步状态不再响应 | 30 秒间隔健康检查中的 5 秒超时触发，回到系统启动台并留下通知；已实际看到“已恢复系统启动台” |

本轮修复两项桌面问题：用运行 ID 驱动恢复弹窗，避免首次展示丢失上下文；SDK 等待异步状态完成，避免把未完成 Promise 当成健康桌面。

## 仍保留的边界

联合更新最多 20 个应用，迁移限用户集合的顶层 rename/default/remove。不兼容工具变更须连同全部已安装调用方一起升级；单应用更新仍拒绝破坏性变化。分组恢复只处理共享数据，遇到后续冲突整组停止；不撤回发送、发布或文件副作用。完整限制见 [04](../architecture/04-app-package.md) 和 [08](../architecture/08-data.md)。

S3/S4/S6 付费模型评测继续按用户决定暂缓。真实账户、Developer ID/公证/签名更新、干净 Mac 发行验收仍未完成。VM 完整内存恢复仍为 `VZErrorDomain Code 12`，没有用冷磁盘恢复替代通过结论。云构建、macOS 来宾、独立应用分享仍是方案中按需扩展的可选产物。
