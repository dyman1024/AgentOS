# 模型凭据保存与验证（2026-10-16）

本轮修复凭据读取错误被误报为“未保存”、更换 Key 后引擎仍复用旧环境，以及钥匙串同步调用阻塞界面的问题。设置新增“验证已保存配置”，保存与在线验证分别显示状态。

## 诊断证据

- 实际桌面对话连续显示 `unavailable: 请先在设置中保存 API Key`；设置当前选择 OpenRouter。
- 钥匙串元数据检查确认 OpenRouter 条目存在，Anthropic 条目不存在。未输出凭据内容。
- 原实现对 `SecItemCopyMatching` 的所有失败都返回空值，随后统一报“请保存 API Key”，丢失了系统错误码。
- 原引擎配置标识只有服务商和模型，Key 替换不触发进程重启。
- 桌面复测中，同步读取已有条目发生长时间等待；进程采样确认主线程停在 `ModelSettings.credentialStatus → CredentialStore.read → SecItemCopyMatching → SecKeychainItemCopyContent → SecurityServer decrypt`。最终设置页改为只查元数据；模型凭据读取和保存通过后台队列执行，并支持 20 秒超时，读取验证可取消。

钥匙串条目存在不代表当前构建已经获得解密权限。没有把 ad-hoc 签名变化推断成已证实的唯一根因，也没有删除真实 Key、放宽访问控制或变更签名配置。

## 实现与验收

| 范围 | 结果与边界 |
|---|---|
| 本机保存 | 去除首尾空白；写入后读回比较，失败保留具体错误；Key 不回显 |
| 错误分类 | 只有条目不存在才允许环境变量回退；权限拒绝、锁定、取消和损坏不再假装未保存 |
| 引擎更新 | 配置在内存中的摘要包含服务商、模型和 Key；更换后下一次运行重启引擎；一轮运行使用一致的配置快照 |
| 设置验证 | Anthropic 读取模型元数据；OpenRouter 先验证当前 Key，再分页查询账户模型；只发 GET，不生成内容 |
| 安全边界 | 不发送聊天、不输出 Key 或服务端响应体；认证请求不跟随重定向；账户余额与实际生成仍未验证 |
| 自动化测试 | 9 项新增 Swift 测试，包含钥匙串实测、4 种读取错误、7 种 HTTP 错误、分页、无效模型/响应、管理 Key 拒绝、超时与取消 |
| 真实宿主 | `scripts/credential-check.py` 在一次性数据根、偏好与钥匙串命名空间中完成保存、替换、服务商隔离及退出重启后的读取；没有真实账户或模型调用 |
| 桌面 | 当前 OpenRouter 保存状态可见，“验证已保存配置”入口可见，未输入新 Key 时保存按钮禁用；打开设置不再等待解密 |

保存超时不表示系统一定没有写入，界面会要求检查保存状态后重试。在线验证通过仅证明认证与模型元数据查询成功，不能替代实际生成验收。真实账户只读验证须按用户本轮授权单独记录。

复现：`make check` 包含 `make credential-test`；后者构建宿主并运行跨进程凭据回归。HTTP 分支测试使用注入响应，未用测试结果冒充真实服务商调用。

本地 `make check` 通过：73 项 Swift 测试、WebKit 沙箱、原生沙箱、4 项 OCI、引擎检查、Debug 构建和跨宿主凭据回归。最终元数据查询移入后台及超时用例确定化后，9 项相关测试、重新构建与跨宿主凭据回归再次通过；[日志摘录](2026-10-16-credentials.txt)保留各次范围。
